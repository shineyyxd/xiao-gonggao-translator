# 小公告翻译官（银发向）

给看不懂公告的退休老人，做一份能听的财经早报。

我在券商营业部实习时，天天看到这样的场景：营业部周边是老龄化社区，退休老人存款不少、
也关心自己手里的股票，但他们获取信息的方式是"楼下问人"——公告看不懂，研报更看不懂，
最容易被噪音带偏。这个项目就是把 A 股上市公司的公告，自动筛选、翻译成老人能听懂的
大白话，每天早上以大字文字 + 音频的形式交给他们。

**只讲事实，不做任何投资建议；宁可停刊，不可错发。**

## 先看效果

一条真实公告进来，出去的是这样三段话（2026-08-28 真实产出）：

> 公告原文标题：《上海农村商业银行股份有限公司2026年中期利润分配方案的公告》
>
> **人话稿**：沪农商行（做银行的）要分钱：每股0.2499元，含税（原文：每10股派2.499元）。
> 你持有1000股，就能拿到249.9元（税前）。只给现金，不给股票。这笔钱不用股东会再点头，
> 你什么都不用办，预计2026年9月24日钱自动到账。
>
> **口播稿（念给老人听的）**："沪农商行，做银行的，要分钱。每股两毛四分九厘九，含税。
> 你持有一千股，就能拿到二百四十九块九，税前……"

更多实物在仓库里：`产出/` 下有各期人话稿、大字版、日报、审计日志；
`产出/老人听测包_0831/audio/` 有真实合成的整期音频（2分48秒）。

## 怎么做的（架构）

```
07:29 定时触发
  ↓ Fetcher    巨潮资讯网实时抓取（约3000条/日，官方披露源）+ 快照落盘 + 完整性对账
  ↓ Editor     三层漏斗：14 赛道分类 + 重要性打分 + 合规过滤 + 多样性控制
  ↓ PdfSummary 入选公告抓 PDF 首页，句子级抽取摘要（只摘不改）
  ↓ Writer     LLM 生成大白话稿（kimi-k3·思考档low；铁律+必解释词表+到手算例）
  ↓ Compliance 确定性预检：数字原值/禁词/关键限定（不过直接打回，不花 LLM 调用）
  ↓ Checker    独立 LLM 校对（kimi-k3·思考档max；A数字错/B无中生有/C倾向话术/D遗漏限定）
  ↓ Publisher  大字版 HTML + 纯文字 + 口播稿 + TTS 音频
全程 Orchestrator 状态机驱动，run_id 全链路审计（audit JSONL + sqlite 双写留痕）。
打回重试 ≤2 次，仍不过这条就不发。
```

## 关键决策（选了什么、没选什么、为什么）

| 决策 | 放弃了什么 | 为什么 |
|---|---|---|
| 编排/记忆层用确定性状态机 | LLM 自主编排 | 调度要可预测、可审计；路径不确定的系统没法追责 |
| 规则漏斗筛选 | RAG / 混合检索 | 每日公告是全量小数据，规则比向量检索更可控；检索在这个场景是过度设计 |
| 链接由管线直接注入 | 让 LLM 生成链接 | v1 实测 LLM 写错 4 处链接；不让它碰就机制性消除这类错误 |
| Writer/Checker 独立模型配置 | 同模型自检 | 避免"自己批自己作业" |
| 写错就枪毙该条 | 宽松放行凑条数 | 用户是老人，信任是核心资产；宁可少发不可错发 |
| 中性事实框架防误读 | 给"偏正面/偏负面"定性 | 定性=投资倾向判断，踩合规红线 |
| sqlite + 本地文件 | 数据库/消息队列等中间件 | 单机日报场景够用，少一个依赖少一个故障点 |

## 怎么评测

- **事实准确率**：每条稿拆成事实核对点逐一对照原文。口径说实话：刊发稿可机检核对点
  通过率 100%（不合格的稿子被拦下了，没发出去）；一次通过率约 60%——后者才是生成
  质量的真实水位，所以日报里两个都记
- **回归集**：每次真实犯过的错误（v1 的 8 处：链接错×4、术语简化×2、无中生有×2，
  加 3 个筛选规则缺陷）全部固化成永久自动化测试，改 prompt/改规则必跑。
  测试总数随迭代增长：47 → 105 → 135 → 148 项
- **选题准头**：运营后每日对照当日大事记漏报/误报
- **老人听懂率**：三问测试（这公司干嘛的？这条讲了什么？跟你啥关系？），
  模拟试测→真人听测两轮

## 我拍了哪些板（没做什么）

- **不做 APP/小程序**——老人在微信里，渠道必须跟着人走，不为技术形态反过来要求用户
- **不配机器人推送通道**——实习生身份不能私下触达客户，产品体验期手动转发即可
- **不给稿子加"定性"**——试过的人建议"每条标偏正面/偏负面"，这是投资倾向判断，踩红线；
  改用有原文出处的中性事实句（"不改变你手里的股数"）解决老人误读
- **不上混合检索**——场景不需要，能讲清边界比硬凑技术栈重要
- **暂缓服务器部署**——先在本地把内容验证到真人听懂，再谈渠道和部署

## 模型实测手记（真摸过这些模型的脾气）

- deepseek-v4-pro/flash 都是推理模型：实测写一条 186 字的稿先思考 5900 token，
  默认 max_tokens=2000 被思考耗尽导致输出为空；同一琐碎提示词 pro 推理占 84.8%、
  flash 占 67.7%——轻任务配轻模型由此而来
- kimi-k2.6/k3 只接受 temperature=1（传 0.2 直接 400）；k3 支持思考档位 low/high/max，
  用于给两个子 Agent 分配思考预算；免费档组织级 RPM=3，客户端内置全局限速
- 余额耗尽（402）当天，管线自动走停刊+告警——容错设计第一次真枪实弹用上
- TTS 选型算过账：Edge TTS（免费）验证内容，火山引擎大模型音色上线（约 0.5 元/天）

## 快速开始

```bash
python3 -m venv pipeline/.venv
pipeline/.venv/bin/pip install -r pipeline/requirements.txt
pipeline/.venv/bin/python -m pytest pipeline/tests -q        # 148 项测试（含真实错误回归集）

# 样本重放（无需 API key，mock 模式确定性出稿）
cd pipeline && .venv/bin/python main.py --date 2026-08-26 --mock-llm --source sample

# 真实 LLM 跑样本：在 pipeline/.env 配置下列环境变量后去掉 --mock-llm
#   YFZB_GEN_API_KEY / YFZB_GEN_MODEL            生成模型
#   YFZB_REV_API_KEY / YFZB_REV_MODEL / YFZB_REV_EFFORT   校对模型（独立配置）
# 生产实时抓取：.venv/bin/python main.py --date <日期> --source live
```

详见 `pipeline/README.md`（场景路由、审计留痕、数据完整性对账口径、配置项全表）、
`架构与版本演进.md`（完整骨架图 + 逐版明细）。
